0 · What is EDA, and why do it first?

Exploratory Data Analysis is the interview you conduct with a dataset before you trust it. Like a doctor's check-up: read the vitals before diagnosing anything. Every chart, model, or conclusion built on unchecked data inherits the data's problems silently.

The three questions EDA answers

  • Check assumptions — is the data what you think it is? Right number of rows, right types, right range?
  • Spot anomalies — missing values, duplicate records, impossible numbers (an age of 200).
  • Find patterns — what does a typical row look like, and what's rare?

⚠️ Why it matters — a one-row demo

2 · Missing Data — drop it or fill it?

  
Missing values appear as NaN. You have two families of fixes: drop (lose rows, keep honesty) or fill / impute (keep rows, introduce a guess). Pick an operation and compare before/after.

How to choose

        
    
          
  • dropna() — default drops a row if any value is missing. Aggressive; can wipe most of a wide table.
    • 
          
  • how="all" — only drop rows that are entirely empty. Safe cleanup.
    • 
          
  • thresh=n — keep rows with at least n real values. The middle ground.
    • 
          
  • fillna(value) — a constant. Careful: filling with 0 pretends a missing measurement was zero.
    • 
          
  • ffill / bfill — carry the neighbouring value. Natural for time series, wrong for unordered rows.
    • 
          
  • fillna(mean) — imputation. Preserves the column average but shrinks its variance.
    • 
        

      

    

    

      

        
Ask "why is it missing?" before you fix it

        

          If values are missing at random (someone skipped a form field), mean-imputation is usually harmless.
          If missingness is systematic — e.g. every international student left "age" blank — the global mean imports a bias into a whole subgroup.
          Dropping 5% of rows is often fine; dropping 40% gives you a different dataset.
        

        
There is no universally correct answer. There is only a decision you can defend.

4 · Outliers — flag, cap, or drop

  
An outlier is a value far from the rest. A patient aged 150 is technically valid and obviously impossible. Two standard ways to find them: the standard-deviation rule and the IQR rule. Then three choices: keep, cap, or remove.

Top: every value as a dot (red = flagged). Bottom: the box plot — the box spans Q1→Q3 (the middle 50%), the green line is the median, the whiskers reach the furthest points inside the 1.5×IQR fence.

      

    

  


  

    

      

        
The IQR rule in one block

        
Q1  = data.quantile(0.25)
Q3  = data.quantile(0.75)
IQR = Q3 - Q1
mask = (data < Q1 - 1.5*IQR) | (data > Q3 + 1.5*IQR)

        
1.5 is convention, not law. Lower k flags more points; higher k flags fewer.

      

    

    

      

        
Which treatment?

        
    
          
  • Flag — always start here. Look at the flagged rows before touching them.
    • 
          
  • Cap (winsorise) — data[data.abs() > 3] = np.sign(data) * 3. Keeps the row, tames the value. Good when the row's other columns matter.
    • 
          
  • Drop — data[(data.abs() < 3).all(axis="columns")]. Right when the value is clearly an error.
    • 
        

        
A real billionaire in an income dataset is not an error. Deleting them makes your analysis wrong, not cleaner.

      

    

  








  
5 · Transformation — map, replace, strings & regex

  
Cleaned data still needs reshaping: turning labels into categories, sentinel codes into NaN, and messy text into structured columns.


  

    

      

        
.map() — look up each value in a dictionary

        

        

          
          
        

        
meat_to_animal = {
  "bacon": "pig",       "pulled pork": "pig",
  "pastrami": "cow",    "corned beef": "cow",
  "honey ham": "pig",   "nova lox": "salmon",
}

        
A value with no dictionary entry becomes NaN — so .map() doubles as a spell-checker for your categories.

Regex cheat-sheet

          
    
            
  • \d a digit · \w letter/digit/underscore · . any character
    • 
            
  • + one or more · * zero or more · ? optional
    • 
            
  • [A-Z] any char in the set · {2,4} between 2 and 4 of them
    • 
            
  • \. a literal dot (the backslash escapes it) · ^ start · $ end
    • 
            
  • ( … ) capture group → becomes one column in .str.extract()
    • 
          

        

      

      

        

          
The three .str methods you'll actually use

          
    
            
  • .str.contains("gmail") → boolean mask for filtering.
    • 
            
  • .str.findall(pat) → a list of every match per row.
    • 
            
  • .str.extract(pat) → a DataFrame, one column per capture group. This is the one that reshapes your data.
    • 
          

          
All of them skip NaN gracefully — that's the point of the .str accessor over a Python loop.

Parameter reference

        
    
          
  • header=None — the file has no header row; use 0,1,2… as column names.
    • 
          
  • names=[…] — supply your own column names.
    • 
          
  • index_col="message" — promote a column to be the row labels.
    • 
          
  • sep="\s+" — a regex separator: "one or more whitespace characters". Handles ragged alignment.
    • 
          
  • skiprows=[0,2,3] — throw away specific line numbers (comments, metadata banners).
    • 
          
  • na_values={…} — declare per-column sentinels that mean "missing".
    • 
        

        
Writing back out: df.to_csv("out.csv", index=False). Without index=False your row numbers become a stray unnamed column that reappears next time you read the file.
